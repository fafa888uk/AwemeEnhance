# 签名与真机安装条件

本项目不购买证书、不索取Apple ID、不上传私钥、不代签名。用户目前选择自行签名。输出IPA是完整重封装但**未签名**的应用，不是开箱即装或已通过App Store验证的安装包。

## 打包工具已检查的结构

- 精确 Bundle ID、41.2.0/41.3.0版本、主可执行文件、arm64架构和插件子类型一致。
- 全部支持的 Mach-O 的加密标志、依赖解析、旧签名剥离、加载命令存在。
- ZIP安全成员、输出CRC、SHA256。

这些检查不验证签名主体、所需entitlements、设备UDID、Apple服务资格、平台账号登录或无恶意代码。静态依赖解析对复杂rpath链、非arm64代码和特殊archive布局可能保守拒绝。

## 由用户签名器完成

1. 使用你已有且有权使用的签名方式及匹配的描述文件；若使用免费个人开发配置，其可用能力与有效期受Apple限制，本项目不承诺一定支持目标应用全部能力。
2. 确认所有嵌套 Framework、dylib、App Extension / App Clip 与主应用均正确签名，通常由内到外；不要对整个包无差别使用 `codesign --deep` 来掩盖嵌套签名错误。
3. Bundle ID、Team ID、application-identifier、keychain-access-groups、App Groups、associated-domains、push等必须与你的授权相符。不能复制不属于你团队的entitlements来“修复登录”。
4. 打包工具移除过期的 `_CodeSignature`、Mach-O签名引用及 `embedded.mobileprovision`，不会自动授予新权限；由签名器嵌入正确描述文件。
5. 有macOS时，用 `codesign --verify --strict --verbose=2` 检查每个嵌套签名目标；审核 `codesign -d --entitlements :-` 输出时注意隐私，不提交原App或账号数据到Issue。
6. 先在备用iPhone测试启动与官方正常行为，再逐个开启模块。仅编译通过不作为功能完成。

## 最小真机验收

- 记录iOS、设备、原IPA SHA256、插件commit/SHA256、签名方式，不记录账号及聊天正文。
- 插件全关闭时启动/播放/导航正常；双指长按入口可开关，不遮挡安全/登录操作。
- 对广告/直播/关键词使用受控样例核对误过滤和空列表；切换推荐/关注/搜索/个人主页。
- 倍速0.25/1/1.5/3、多视频切换；最高画质与弱网降级；短视频滑块拖动及直播不误处理。
- 隐藏导航/按钮后可恢复；深色模式、大字体、iPad弹窗。
- 原片仅用本人授权素材核验权限，禁止尝试禁存或付费视频。
- 火花权限拒绝、关闭、重启、跨天/时区、重复触发、写盘失败；通知不显示好友/消息；记录不宣称服务端成功。
- 完整IPA重新签名后的首次/再次启动、休眠恢复、系统通知、崩溃及内存情况。

当前没有目标IPA/设备完成上述测试，所有相关格子均保持待验证。
